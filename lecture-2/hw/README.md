# ToDo List API

Нужно доработать тудулист из прошлого домашнего задания так, чтобы задачи хранились на сервере.

## Что должно уметь приложение

- Загружать задачи с сервера при открытии страницы
- Добавлять новую задачу через сервер
- Удалять задачу через сервер
- Отмечать задачу как выполненную через сервер
- Искать задачу по тексту
- Фильтровать задачи: все / активные / выполненные
- Показывать количество задач: всего, активных, выполненных
- Удалять все выполненные задачи через сервер

## Сервер

```text
http://212.193.11.210:3000
```

У каждого ученика свой список задач. Для этого во все запросы к задачам нужно передавать header:

```text
X-Student-Id
```

Значение header — ваш номер от `1` до `15`.

## Структура задачи

Сервер возвращает задачу в таком формате:

```js
{
  id: 1,
  student_id: 1,
  title: 'Купить хлеб',
  completed: false,
  created_at: '...',
  updated_at: '...'
}
```

Обратите внимание: в прошлом домашнем задании текст задачи мог храниться в поле `text`, а сервер использует поле `title`.

## Ручки API

Все ручки работают со списком конкретного ученика. Для них нужен header `X-Student-Id`.

### Получить задачи

```http
GET /todos
```

Возвращает массив задач ученика.

### Создать задачу

```http
POST /todos
```

Body:

```js
{
  title: 'Новая задача'
}
```

Возвращает созданную задачу.

### Получить одну задачу

```http
GET /todos/:id
```

Возвращает задачу по `id`.

Если задача принадлежит другому ученику, сервер вернёт ошибку.

### Обновить задачу

```http
PATCH /todos/:id
```

Body может содержать одно или оба поля:

```js
{
  title: 'Новый текст',
  completed: true
}
```

Возвращает обновлённую задачу.

### Удалить задачу

```http
DELETE /todos/:id
```

Удаляет задачу по `id`.

## Требования

- При загрузке страницы нужно получить задачи с сервера
- В input пользователь пишет текст задачи
- По нажатию на кнопку или Enter задача создаётся на сервере
- Если строка пустая — ничего не отправлять
- После успешного добавления поле ввода очищается
- У каждой задачи должна быть кнопка удаления
- У каждой задачи должен быть checkbox для статуса выполнения
- При изменении checkbox задача должна обновляться на сервере
- Выполненная задача должна визуально отличаться: текст перечёркнут
- Поиск должен фильтровать список по подстроке
- Фильтры должны показывать только нужные задачи
- Счётчики должны обновляться после любых изменений
- После перезагрузки страницы задачи не должны пропадать

## Важно

- Не храните задачи только локально в массиве
- Массив на фронте можно использовать для отображения, но источник данных — сервер
- Для создания и обновления задач отправляйте JSON
- Не забывайте `X-Student-Id`
- Если сервер возвращает ошибку, покажите её в `alert` или в интерфейсе

## Дополнительно

Можно сделать:
- состояние загрузки при первом получении задач
- состояние "Сохраняем..." при добавлении задачи
- состояние "Удаляем..." при удалении задачи
- блокировку кнопок во время запроса
- сообщение, если сервер недоступен
- пустое состояние, если ничего не найдено

## Bonus: API-функции

Вынесите работу с сервером в отдельные функции:

- `getTodos()`
- `createTodo(title)`
- `updateTodo(id, data)`
- `deleteTodo(id)`

### Что проверить

- функции ничего не рисуют на странице
- функции только делают запросы и возвращают данные
- интерфейс обновляется после успешного ответа сервера

## Bonus: async/await

Используйте `async/await` для работы с запросами.

Задание:
- обработайте ошибки через `try/catch`
- не обновляйте интерфейс до успешного ответа сервера
- верните кнопку в обычное состояние после завершения запроса

### Что проверить

- при ошибке приложение не ломается
- пользователь понимает, что что-то пошло не так
- повторные клики по кнопкам не создают странное поведение

## Подсказка

Сначала сделайте загрузку списка с сервера.

Потом по очереди подключайте:

1. добавление
2. удаление
3. обновление checkbox
4. удаление выполненных задач

## Ожидаемый результат

Приложение должно работать без перезагрузки страницы, но все изменения должны сохраняться на сервере.
